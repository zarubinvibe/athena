# Онбординг

Этот путь написан так, будто вы настраиваете Mac с нуля и никогда не пользовались агентной ОС. На каждом шаге сказано, что сделать и что вы должны увидеть.

Короткий путь — разговорный: откройте проект в Claude Code и запустите `/athena-setup`. Афина поставит себя сама, слой за слоем, покажет сухой прогон до записи и ничего не поставит без вашего «да». Ниже — та же дорога пешком.

Athena работает на macOS. Нужны учетная запись администратора и сеть для Homebrew, npm и Git.

1. **Заберите проект и прочитайте установщик до запуска.**

   ```bash
   git clone https://github.com/zarubinvibe/athena.git "$HOME/athena"
   cd "$HOME/athena"
   less preinstall.sh
   ```

   Вы увидите скрипт, который собираетесь запустить. Прочитать его — это смысл шага, а не формальность.

2. **Первый шаг руками.**

   ```bash
   ./preinstall.sh
   ```

   Вы увидите, как ставятся Xcode Command Line Tools, Homebrew, chezmoi, Node.js, Git и закрепленная версия Claude Code. Этому шагу нужен пароль вашего Mac: его нельзя делегировать.

3. **Откройте Claude Code в репозитории.**

   ```bash
   claude
   ```

   Вы увидите, что агент запустился внутри папки проекта.

4. **Запустите ведомую установку.** Введите `/athena-setup` и отвечайте по одному вопросу. К каждому сказано, зачем он и как выглядит хороший ответ.

   Вы увидите, что ваши ответы записаны как конфигурация вашей машины, а не чьей-то чужой.

5. **Посмотрите план до того, как что-то запишется.**

   ```bash
   ./bootstrap.sh --dry-run
   ```

   Вы увидите, что сделал бы каждый слой. Во время просмотра ничего не ставится, не клонируется и не перезаписывается.

6. **Соберите слои.** Инструменты, файлы настроек, плагины, реестр возможностей, ваши проекты, необязательная база знаний, хранилище секретов и фоновые задания — в этом порядке.

   Вы увидите среду, где агенты, скиллы и проекты снова на месте.

7. **Намеренно повторите один слой.**

   ```bash
   ./bootstrap.sh --only=6
   ```

   Вы увидите, что он спокойно отработал еще раз. Слои сделаны повторяемыми: второй запуск не риск.

8. **Проверьте результат.**

   ```bash
   shellcheck -S error bootstrap.sh preinstall.sh smoke/*.sh
   bash smoke/smoke.sh
   ```

   Вы увидите зеленые проверки или названные файл и строку, которые надо починить.

9. **Следите за состоянием.**

   ```bash
   node "$HOME/.agents/registry/scripts/athena-status.mjs" --days=7
   ```

   Вы увидите, не сломалось ли что-то тихо за неделю. Команда краснеет, если задание упало и не было повторено.

10. **Закончите на своей настоящей работе, а не на примере.** Откройте в собранной среде свой проект и сделайте одну реальную задачу. Установка, на которой ни разу не запускали настоящее, не закончена.

## Как обновляться дальше

Когда выйдет новая версия, не клонируйте заново: откройте проект в Claude Code и запустите `/athena-update`. Он сначала делает резервную копию, показывает разницу до применения, тянет изменения только вперед, не трогает ваш личный слой, ключи, проекты и базу знаний и после обновления прогоняет проверки.

## Если это помогло

Если Athena вернула вам вашу среду, поставьте звезду: [https://github.com/zarubinvibe/athena](https://github.com/zarubinvibe/athena). Это секунда, а от нее зависит, найдут ли проект другие.

Вы прошли путь целиком, значит, вы и есть тот, кто может его улучшить. Дорога короткая: сделайте fork, заведите ветку, оформите commit, отправьте push и откройте Pull Request. Прямой push в `main` релизный gate отклонит.

Шаг соврал? Заведите issue на [https://github.com/zarubinvibe/athena/issues](https://github.com/zarubinvibe/athena/issues) и напишите, что запускали и что увидели.
