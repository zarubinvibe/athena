# Обновление Athena

Первая установка — это `/athena-setup`. Здесь обновляется уже собранная среда.

## Правила

**1. Сначала показать, потом делать.** Сказать, какая версия стоит и какая опубликована, и показать разницу настроек до применения.

**2. Резервная копия обязательна.** Живые настройки перезаписываются только после бэкапа, и человек слышит, где он лежит.

**3. Грязное дерево — стоп.** Незакоммиченные правки назвать поименно и остановиться.

**4. Только вперед.** `git pull --ff-only`. Разошедшуюся историю показать, а не «чинить» силой.

**5. Не трогать твое.** Обновление не касается личного слоя, ключей, клонированных проектов и базы знаний.

**6. Проверить себя после.** Прогнать smoke-проверки и назвать результат как есть.

## Ход обновления

```bash
git -C . status --short
git -C . pull --ff-only
./bootstrap.sh --dry-run
bash smoke/smoke.sh
```

Что человек увидит: список изменившихся файлов, затем полный план изменений средой, затем результат проверок. Применять живые изменения только после явного «да».

## Если обновление не проходит

- **Есть локальные правки.** Назвать файлы, предложить закоммитить или отложить. Не выбирать за человека.
- **История разошлась.** Объяснить простыми словами и дать выбрать.
- **Проверка красная.** Назвать файл и строку и предложить откат на прежнюю версию одной командой.
